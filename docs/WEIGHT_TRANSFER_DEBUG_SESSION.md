# Weight Transfer Debug Session - Documentation

**Date:** 2026-02-16  
**Context:** Debugging mesh crumpling and weight transfer issues in Spoken Wardrobe v2  
**Status:** IN PROGRESS - Partial fixes implemented, core issue identified

---

## Problem Statement

The weight transfer system for clothing meshes generated by Rodin API was failing with the following symptoms:
1. **Mesh crumpling/exploding** when weight transfer was applied
2. **6000+ vertices with zero weight** out of ~7000 total vertices
3. **Most vertices assigned to spine bone** (bone 0) regardless of position
4. **Half of clothing mesh invisible** or severely distorted

### Root Cause Identified

The body mesh (`lowpoly_rigged_full_v1.glb`) has **poor vertex distribution**:
- **41% of vertices (392/956) weighted to spine**
- Only ~60-110 vertices per limb
- When clothing vertices search for closest body vertex, most find spine vertices
- This causes incorrect weight assignment and deformation artifacts

### Secondary Issues Found

1. **Skeleton bind matrices were calculated for posed bones**, not rest pose
2. **Clothing mesh not aligned** with body mesh (different coordinate spaces)
3. **Body mesh not being properly cleaned up** when loading new meshes
4. **Closest-point search was vertex-to-vertex** instead of vertex-to-surface

#### Change 4: Skeleton Reset to Rest Pose (ADDED)
```javascript
// Lines 213-246 - ADD new method _resetSkeletonToRestPose()
_resetSkeletonToRestPose() {
    if (!this.skeleton) return;
    const bones = this.skeleton.bones;
    let nonRestCount = 0;
    
    // Check current state
    bones.forEach(bone => {
        const isIdentity = bone.matrixWorld.elements.every((v, idx) => {
            const expected = idx === 0 || idx === 5 || idx === 10 || idx === 15 ? 1 : 0;
            return Math.abs(v - expected) < 0.001;
        });
        if (!isIdentity) nonRestCount++;
    });
    
    if (nonRestCount > 0) {
        console.log(`[ThreeScene] Found ${nonRestCount} bones not in rest pose, resetting...`);
        bones.forEach(bone => {
            bone.position.set(0, 0, 0);
            bone.quaternion.set(0, 0, 0, 1);
            bone.scale.set(1, 1, 1);
            bone.updateMatrix();
        });
        this.bodyMesh.updateMatrixWorld(true);
        this.skeleton.update();
        this.skeleton.calculateInverses();
        console.log('[ThreeScene] Skeleton reset to rest pose');
    }
}
```

## Key Discoveries

### 1. Body Mesh is the Primary Issue
- Original `lowpoly_rigged_full_v1.glb` has only 956 vertices
- 41% of vertices (392) are weighted to spine
- Arms and legs have only 60-110 vertices each
- This causes clothing vertices to match to spine instead of limbs

### 2. Skeleton Bind Matrices
- GLB was exported with bones in posed position (A-pose)
- Bind matrices were calculated for this posed state
- Attempting to reset to rest pose breaks the skinning
- Solution: Use skeleton as-is from GLB, don't modify bind matrices

### 3. Coordinate Space Alignment
- Clothing meshes from Rodin are at origin (Y=0)
- Body mesh is at Y=0.817
- Without alignment, clothing vertices can't find matching body vertices
- Solution: Transform clothing to body space before weight transfer

### 4. Vertex-to-Vertex Search is Insufficient
- Brute force closest-vertex search fails with sparse body mesh
- Many clothing vertices fall between body vertices
- Solution: Use BVH closest-point-on-surface with barycentric interpolation

2. ❌ **Weight transfer still results in ~6000 zero-weight vertices** - Body mesh coverage is insufficient
3. ❌ **Mesh still explodes/collapses** - Likely due to incorrect bind matrices or vertex positions

### Recommended Next Steps
1. **Get a higher-resolution body mesh** with even vertex distribution:
   - Minimum 2000-5000 vertices
   - No more than 15-20% of vertices on any single bone
   - Even coverage across all body parts

2. **Verify the new body mesh** using the diagnostic tool:
   - Load new mesh
   - Check bone distribution percentages in console
   - Ensure spine is < 20% of total vertices

3. **Test weight transfer** with new mesh:
   - Should see more even bone distribution
   - Should have < 1000 zero-weight vertices
   - Clothing should not explode

4. **Alternative approach:** If new body mesh doesn't fix it, consider:
   - Rigid transform only (no skeletal animation)
   - Pre-rigged clothing meshes
   - SMPL-X body model approach
